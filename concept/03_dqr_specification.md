# 1. 핵심 아이디어 — 스칼라에서 벡터로

## 1.1 딥러닝에서 얻은 통찰

딥러닝의 Convolutional Neural Network에서 feature map은 다음 텐서다:

$$\text{feature map} \in \mathbb{R}^{H \times W \times C}$$

각 위치 (i,j)에는 C-차원 벡터가 있다. 이 C개의 채널이 각자 다른 특성(엣지, 질감, 색상 등)을 인코딩한다.

**QR 코드는 C=1인 특수 케이스다.**

$$\text{QR code} \in \{0, 1\}^{H \times W \times 1}$$

## 1.2 진화 경로

```
QR:      T[i,j] ∈ {0, 1}                 → C=1, 1 bit/module
JAB:     T[i,j] ∈ {0,...,7}              → C=1 (색상 스칼라), 3 bits/module
D_QR:    T[i,j] ∈ ℤ^{d₁} × ℤ^{d₂} × ... → C=D (다차원 벡터), N bits/module
```

## 1.3 핵심 주장

> 각 모듈 위치 (i,j)에 **독립적으로 디코딩 가능한 D개 채널**을 부여하면,  
> 동일 면적에서 D배(이론값)의 정보를 담을 수 있다.

"독립적으로 디코딩 가능"이 핵심 조건이다.  
채널 간 물리적 독립성이 보장되어야 하며, 각 채널은 자체 ECC를 가진다.

# 2. D_QR 텐서 표현의 공식 정의

## 2.1 기본 텐서

$$\mathbf{T} \in \mathbb{Z}^{H \times W \times D}$$

- $H, W$ : 격자의 행/열 모듈 수
- $D$ : 인코딩 깊이 (차원 수)
- $T[i,j,:] \in \mathbb{Z}^D$ : 위치 (i,j)의 D-차원 정수 벡터

## 2.2 각 모듈 값의 범위

$$T[i,j,k] \in \{0, 1, ..., L_k - 1\}$$

여기서 $L_k$는 k번째 차원의 레벨 수. 이 차원이 담는 비트 수:

$$b_k = \lfloor \log_2 L_k \rfloor$$

전체 모듈당 비트 수:

$$B_{module} = \sum_{k=0}^{D-1} b_k$$

## 2.3 전체 데이터 용량

$$C_{total} = \frac{(H \times W - M_{func}) \times B_{module}}{8} \text{ bytes}$$

- $M_{func}$ : 파인더/타이밍/정렬 패턴 등 기능 모듈 수
- $(H \times W - M_{func})$ : 실제 데이터 모듈 수

# 3. 차원별 물리적 표현과 비트 용량

## 3.1 Phase 1 차원 설계 (색상 3채널)

첫 번째 단계: 색상만으로 다차원 확장.

$$T[i,j,:] = (c_1, c_2, c_3)$$

| 차원 | 물리적 표현 | 레벨 수 ($L_k$) | 비트 ($b_k$) | 구현 난이도 |
|------|-----------|--------------|------------|-----------|
| $c_1$ | 색조(Hue) | 8 | 3 bits | ✅ 높음 |
| $c_2$ | 채도(Saturation) | 4 | 2 bits | ⚠️ 중간 |
| $c_3$ | 명도(Value) | 4 | 2 bits | ✅ 높음 |
| **합계** | | | **7 bits/module** | |

QR 대비 **7배** 이론 용량.

## 3.2 Phase 2 차원 설계 (색상 + 패턴)

두 번째 단계: 모듈 내부에 기하학적 패턴 추가.

$$T[i,j,:] = (c_1, c_2, c_3, p_1, p_2)$$

| 차원 | 물리적 표현 | 레벨 수 | 비트 | 구현 조건 |
|------|-----------|--------|------|---------|
| $p_1$ | 내부 선 방향 (0°, 45°, 90°, 135°, ...) | 8 | 3 bits | 모듈 크기 ≥ 10px |
| $p_2$ | 내부 패턴 종류 (점/선/격자/사선) | 4 | 2 bits | 모듈 크기 ≥ 16px |
| **Phase 2 합계** | | | **12 bits/module** | |

## 3.3 Phase 3 차원 설계 (색상 + 패턴 + 주파수)

세 번째 단계: DCT 주파수 도메인 활용.

$$T[i,j,:] = (c_1, c_2, c_3, p_1, p_2, f_1, f_2)$$

| 차원 | 물리적 표현 | 레벨 수 | 비트 | 구현 조건 |
|------|-----------|--------|------|---------|
| $f_1$ | DCT 저주파 계수 부호 (4개 상태) | 4 | 2 bits | 화면 전용 |
| $f_2$ | DCT 고주파 계수 부호 (2개 상태) | 2 | 1 bit | 화면 전용 |
| **Phase 3 합계** | | | **15 bits/module** | |

## 3.4 현실 보정 계수

각 차원의 실제 정보량은 채널 노이즈로 감소:

$$b_k^{eff} = b_k \times (1 - BER_k)$$

여기서 $BER_k$는 k번째 채널의 비트 오류율.

| 차원 | 이론 비트 | 예상 BER | 실효 비트 |
|------|--------|---------|---------|
| $c_1$ (색조) | 3 | 5% | 2.85 |
| $c_2$ (채도) | 2 | 15% | 1.70 |
| $c_3$ (명도) | 2 | 8% | 1.84 |
| **합계** | **7** | | **~6.4 bits** |

ECC 오버헤드 포함 시 실용 용량: **~4.5 bits/module** (ECC-M 수준).

# 4. 인코딩 함수 E

## 4.1 정의

$$E : \{0,1\}^N \rightarrow \mathbb{Z}^{H \times W \times D}$$

비트스트림 $\mathbf{b} \in \{0,1\}^N$을 D_QR 텐서로 변환.

## 4.2 단계별 알고리즘

```
입력: 비트스트림 b ∈ {0,1}^N

1단계: 채널별 비트 분할
   b → (b_c1, b_c2, b_c3, b_p1, ...)
   각 채널 k가 담당할 비트 b_k 분리

2단계: 채널별 ECC 인코딩
   b_k → RS_encode(b_k, rate_k) → c_k
   채널마다 독립적 Reed-Solomon 적용

3단계: 인터리빙 (burst error 방지)
   c_k → interleave(c_k) → c_k_interleaved

4단계: 비트 → 심볼 변환
   c_k_interleaved (비트) → s_k (L_k-진법 심볼)
   b_k개씩 묶어서 0~(L_k-1) 범위 정수로 변환

5단계: 텐서 배치
   각 s_k를 T[i,j,k]에 사문형 경로로 배치
   (기능 모듈 위치는 건너뜀)

출력: T ∈ Z^{H×W×D}
```

## 4.3 채널 우선순위 설계

신뢰도가 높은 채널에 더 중요한 데이터를 할당:

```
c_1 (색조, 높은 신뢰도)   → 가장 중요한 데이터 비트
c_3 (명도, 중간 신뢰도)   → 보통 중요도 데이터
c_2 (채도, 낮은 신뢰도)   → 오류정정 코드워드 or 낮은 중요도
f_1 (DCT 저주파, 화면 전용) → 보조 데이터
```

# 5. 렌더링 함수 R

## 5.1 정의

$$R : \mathbb{Z}^{H \times W \times D} \rightarrow \mathbb{R}^{(H \cdot m) \times (W \cdot m) \times 3}$$

텐서 $\mathbf{T}$를 픽셀 이미지로 변환. $m$ = 모듈당 픽셀 크기.

## 5.2 단계별 렌더링

```
입력: T[i,j,:] = (c₁, c₂, c₃, p₁, p₂)

1단계: 색상 심볼 → HSV 변환
   H = c₁ × (360 / L_{c₁})   (색조각도)
   S = 0.5 + c₂ × (0.5 / (L_{c₂}-1))   (채도 0.5~1.0)
   V = 0.5 + c₃ × (0.5 / (L_{c₃}-1))   (명도 0.5~1.0)

2단계: HSV → RGB
   (H, S, V) → (R, G, B) 표준 변환

3단계: m×m 베이스 패치 생성
   배경 픽셀 = (R, G, B)로 채움

4단계: 패턴 오버레이 (Phase 2 이상)
   p₁으로 선 방향 결정 (0=가로, 1=45°, 2=세로, ...)
   p₂로 패턴 종류 결정 (0=없음, 1=점, 2=선, 3=격자)
   배경 위에 대비 색상으로 패턴 그리기

출력: m×m 픽셀 패치
```

## 5.3 파인더 패턴과 기능 모듈

기존 QR의 파인더 패턴(흑백) 재사용:
- D_QR도 3개 코너에 7×7 흑백 파인더 패턴 유지
- 타이밍 패턴: 흑백 교대 유지
- 포맷 정보: 차원 수 D, 각 채널 L_k, ECC 레벨 포함 (확장 필요)

# 6. 디코딩 함수 D

## 6.1 정의

$$D : \mathbb{R}^{(H \cdot m) \times (W \cdot m) \times 3} \rightarrow \{0,1\}^N$$

캡처된 이미지에서 원본 비트스트림 복원.

## 6.2 단계별 디코딩 알고리즘

```
입력: 촬영된 이미지 (카메라/스크린샷)

1단계: 파인더 패턴 감지
   이미지에서 1:1:3:1:1 비율 탐색
   3개 파인더 위치로 호모그래피 행렬 H 계산

2단계: 호모그래피 보정
   이미지 → H^{-1} 적용 → 정규화된 격자 이미지

3단계: 모듈 중심 픽셀 추출
   각 (i,j) 위치 중심 영역 평균 RGB 추출

4단계: 채널별 심볼 복원
   RGB → HSV 변환
   H값 → c₁ 심볼 (최근접 팔레트 매핑)
   S값 → c₂ 심볼
   V값 → c₃ 심볼

   (Phase 2) 패치 내 패턴 분석 → p₁, p₂ 심볼

5단계: 채널별 ECC 디코딩
   각 채널 심볼 → RS_decode → 오류 정정된 비트

6단계: 채널 비트 재조합
   (b_c1, b_c2, ...) → 원본 비트스트림 b

출력: b ∈ {0,1}^N
```

## 6.3 딥러닝 기반 디코딩 (Phase 2+)

패턴 채널(p₁, p₂) 디코딩은 CNN 분류기로 대체:

```
모듈 패치 (m×m×3) → CNN → [p₁ 클래스, p₂ 클래스]
```

학습 데이터: 다양한 조명/거리/각도에서 촬영한 D_QR 패치  
장점: 노이즈와 왜곡에 훨씬 강인한 패턴 인식 가능

# 7. 다차원 마스킹 설계

## 7.1 기존 QR 마스킹의 한계

QR의 8개 마스크는 이진(흑/백) 데이터에만 작동.  
다차원 심볼에는 새로운 마스킹 전략이 필요하다.

## 7.2 채널별 독립 마스킹

각 차원 k에 대해 독립적 마스크 함수 $M_k(i,j)$ 정의:

$$T'[i,j,k] = (T[i,j,k] + M_k(i,j)) \mod L_k$$

마스크 함수 후보:

| 차원 | 마스크 종류 | 수식 |
|------|-----------|------|
| $c_1$ (색조) | 색상 순열 마스크 | $(c_1 + f_H(i,j)) \mod 8$ |
| $c_2$ (채도) | 이진 XOR 마스크 | $c_2 \oplus f_S(i,j)$ |
| $c_3$ (명도) | 이진 XOR 마스크 | $c_3 \oplus f_V(i,j)$ |
| $p_1$ (방향) | 방향 회전 마스크 | $(p_1 + f_P(i,j)) \mod 8$ |

## 7.3 최적 마스크 선택

QR과 동일한 접근: 채널별 페널티 점수 계산 후 조합 최적화.

```
채널 0의 최적 마스크: arg min_{m} Penalty(T'[:,:,0] | mask_m)
채널 1의 최적 마스크: arg min_{m} Penalty(T'[:,:,1] | mask_m)
...
```

각 채널 독립적으로 최적 마스크 선택 가능.

# 8. 채널별 Reed-Solomon ECC 확장

## 8.1 기존 RS의 한계

QR의 RS는 GF(256) = GF(2⁸) 위에서 동작. 이진 심볼 전용.  
다중 레벨 심볼(L_k > 2인 경우)에는 GF(q) 확장 필드 필요.

## 8.2 채널별 유한체 선택

$$\text{채널 } k : \text{GF}(L_k^r) \text{ 위의 RS 코드}$$

| 채널 | 레벨 ($L_k$) | 유한체 | RS 설계 |
|------|------------|-------|-------|
| $c_1$ (색조) | 8 = 2³ | GF(2³) | 8진법 RS |
| $c_2$ (채도) | 4 = 2² | GF(2²) | 4진법 RS |
| $c_3$ (명도) | 4 = 2² | GF(2²) | 4진법 RS |
| $p_1$ (방향) | 8 = 2³ | GF(2³) | 8진법 RS |

> GF(2^m) 위의 RS는 표준 이론으로 설계 가능.  
> 12진법 등 2의 제곱이 아닌 레벨은 더 복잡한 유한체 필요 → 설계 회피.

## 8.3 채널별 ECC 레이트 차등 적용

신뢰도가 낮은 채널에 더 강한 ECC 적용:

```
채널 신뢰도: c₁ > c₃ > c₂ > p₁ > p₂ > f₁

ECC 레이트 (낮을수록 더 강한 ECC):
c₁: rate = 0.7  (데이터 70%, ECC 30%)
c₃: rate = 0.65
c₂: rate = 0.55
p₁: rate = 0.5
p₂: rate = 0.45
f₁: rate = 0.4
```

## 8.4 채널 간 크로스 ECC (선택적)

핵심 데이터를 여러 채널에 중복 저장하는 방식:

```
중요 비트 → c₁에 저장 + c₃에도 일부 복사
→ 두 채널 모두 손상되어야만 데이터 손실
```

# 9. 딥러닝 차원 (Neural D_QR)

## 9.1 개념

기존 D_QR이 **규칙 기반(rule-based)** 인코딩이라면,  
Neural D_QR은 **신경망 학습(learned)** 인코딩이다.

$$\text{Encoder} : \{0,1\}^N \rightarrow \mathbb{R}^{H \times W \times 3} \quad \text{(신경망)}$$
$$\text{Decoder} : \mathbb{R}^{H \times W \times 3} \rightarrow \{0,1\}^N \quad \text{(신경망)}$$

## 9.2 오토인코더 기반 설계

```
데이터 b
    ↓ Encoder (MLP/CNN)
시각 코드 이미지 (H×W×3)
    ↓ 이미지 손상 시뮬레이션 (노이즈, 블러, 조명 변화)
손상된 이미지
    ↓ Decoder (CNN)
복원된 데이터 b'

손실: L = ||b - b'||² + λ × Perceptual_Loss(image)
```

## 9.3 딥러닝 차원의 잠재적 우위

| 비교 항목 | Rule-based D_QR | Neural D_QR |
|---------|----------------|------------|
| 디코딩 방법 | 고정 알고리즘 | 학습된 신경망 |
| 노이즈 강건성 | ECC 의존 | 학습으로 적응 |
| 용량 | 사전 정의된 비트/모듈 | 이론적으로 최적 |
| 해석 가능성 | ✅ 완전 투명 | ⚠️ 블랙박스 |
| 구현 복잡도 | 낮음 | 높음 |
| 디코더 배포 | 앱에 알고리즘 내장 | 앱에 모델 내장 |

## 9.4 Destiny 엔그램과의 철학적 연결

Destiny 게임의 엔그램이 "정보가 어딘가에 담겨있는 미지의 객체"이듯,  
Neural D_QR은 "신경망이 데이터를 시각 패턴으로 변환한 것" — 인간이 규칙을 정의하지 않아도 된다.

```
전통 QR: 인간이 설계한 규칙 → 기계가 실행
Neural D_QR: 기계가 규칙을 발견 → 인간은 결과만 사용
```

이는 마신강림 TQC 코드가 "다차원 정보를 2D 표면에 투영한 방식"이라는 아이디어와 같다.

# 10. 설계 원칙 및 트레이드오프

## 10.1 세 가지 핵심 트레이드오프

### 트레이드오프 1: 모듈 크기 vs 패턴 해상도

```
모듈 크기 m 증가 → 패턴 디코딩 정확도 증가 → 코드 물리 크기 증가
모듈 크기 m 감소 → 코드 크기 감소 → 패턴 차원 사용 불가
```

Phase 1 (색상만): m = 4px으로 충분  
Phase 2 (패턴 추가): m ≥ 10px 필요

### 트레이드오프 2: 채널 수 vs 디코딩 복잡도

```
채널 D 증가 → 용량 증가 → 디코딩 오류율 증가 → ECC 오버헤드 증가
```

Phase 1: D=3 (색상 3채널) → 안전하고 검증 가능  
Phase 3: D=7 → 이론적으로 좋지만 실용성 미확인

### 트레이드오프 3: ECC 강도 vs 실효 용량

```
ECC 레이트 감소 → 복구 능력 증가 → 실효 데이터 용량 감소
```

최적점: 채널별 BER을 측정하고 채널별로 최적 ECC 레이트 선택.

## 10.2 인쇄 vs 화면 전용

| 차원 | 인쇄 적용 | 화면 전용 |
|------|---------|---------|
| 색상 3채널 | ✅ (제한적) | ✅ |
| 패턴 방향 | ⚠️ (고DPI 인쇄만) | ✅ |
| DCT 주파수 | ❌ (인쇄 시 고주파 소실) | ✅ |

D_QR 초기 단계는 **화면 전용**으로 개발하고, 이후 인쇄 버전을 별도 설계한다.

# 11. 미해결 문제 및 향후 과제

## 11.1 핵심 미해결 문제

**문제 1: 색상 팔레트 최적화**  
8색이 최적인가? 카메라와 디스플레이의 실제 색 분리 가능 범위에서 몇 가지 색이 실용적인지 측정 필요.

**문제 2: 포맷 정보 확장**  
QR의 15비트 포맷 정보로는 D_QR의 메타데이터(D, L_k, ECC 레이트)를 담기 부족. 포맷 정보 구조 재설계 필요.

**문제 3: 파인더 패턴 재사용 vs 재설계**  
기존 QR 파인더 패턴을 재사용하면 기존 QR 리더가 D_QR을 오검출할 수 있음. 전용 파인더 패턴 설계 고려.

**문제 4: 채널별 BER 실측 데이터**  
현재 BER 추정값은 이론적. 실제 스마트폰 카메라로 촬영한 D_QR의 채널별 BER을 실측해야 함.

## 11.2 검증이 필요한 것들

1. **색상 팔레트 분리 실험** ✅ 필요 — Python으로 색상 패치 생성, 카메라 촬영, 오인식률 측정
2. **왕복 테스트** ✅ 필요 — encode → render → decode → 원본 일치 확인
3. **용량 벤치마크** ✅ 필요 — QR/JAB/D_QR 동일 면적 용량 비교
4. **노이즈 민감도** ⚠️ 선택 — 조명, 기울기, 거리에 따른 오류율

## 11.3 구현 로드맵

```
Phase 1: 색상 3채널 D_QR
  → encoder.py + renderer.py + decoder.py
  → 왕복 테스트 통과
  → QR 대비 5배 용량 달성 목표

Phase 2: 패턴 차원 추가
  → 패턴 렌더러 + CNN 패턴 디코더
  → 10배 용량 목표

Phase 3: 주파수 차원 (화면 전용)
  → DCT 인코딩/디코딩 모듈
  → 14배 용량 목표

Phase 4: Neural D_QR
  → 오토인코더 학습
  → 이론적 최대 용량 탐색
```
