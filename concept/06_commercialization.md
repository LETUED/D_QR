# 1. QR 창시자는 어떻게 했는가 — 교훈과 한계

## 1.1 실제로 일어난 일

```
하라 마사히로 (Masahiro Hara) — 덴소 웨이브 (Denso Wave) 직원
1994년: 자동차 부품 추적용 QR 코드 개발
        → 특허: 개인이 아닌 덴소 웨이브(회사) 소유
        → 수익화 전략: 특허 보유 + 로열티 무료 공개

결과:
  ✅ QR 코드가 전 세계 표준이 됨 (10억+ 개/일 스캔)
  ✅ 창시자는 역사에 이름을 남김 (IEEE 소비자기술 어워드 2014)
  ❌ 개인 수익: 거의 없음 (회사 소속 발명, 회사가 직접 수익화)
  ❌ 덴소 웨이브 자체도 QR 특허로 직접 돈을 크게 번 것은 아님
      → 표준이 되는 대신 로열티를 포기한 전략
```

## 1.2 왜 로열티를 무료로 했는가

```
딜레마:
  로열티 받음 → 기업들이 안 씀 → 표준 못 됨 → 아무도 모름
  로열티 무료 → 기업들이 씀 → 표준 됨 → 간접 이익 (회사 명성)

덴소 웨이브의 선택: 표준화 >> 직접 수익
이유: 덴소의 본업(자동차 부품)에 QR이 쓰이면 그것으로 충분
```

## 1.3 D_QR에서 반복하면 안 되는 실수

```
실수 1: 회사 소속으로 개발
  → 특허권이 회사로 넘어감
  → 동환이 직접 수익을 받을 수 없음

실수 2: 무조건 오픈소스
  → 아무도 안 쓰면 의미 없지만
  → 너무 일찍 공개하면 특허 기회 소멸
  → 특허 출원 BEFORE 오픈소스

실수 3: 너무 빨리 표준화 추진
  → 지금은 프로토타입조차 없음
  → 표준화는 작동하는 코드 이후
```

# 2. D_QR과 QR의 차이 — 왜 수익화 전략이 달라야 하는가

## 2.1 구조적 차이

| 항목 | QR 코드 | D_QR |
|------|---------|------|
| 디코더 | 레이저 스캐너 (단순 하드웨어) | 스마트폰 + AI 소프트웨어 |
| 복잡도 | 알고리즘 단순 | AI 모델 + 다차원 ECC |
| 복제 가능성 | 공식 스펙 보면 누구나 구현 가능 | AI 모델과 세부 구현이 핵심 |
| 수익화 가능성 | 낮음 (너무 단순) | **높음 (소프트웨어 레이어 존재)** |

## 2.2 D_QR이 수익화에 유리한 이유

```
QR: 알고리즘 공개 = 끝. 아무나 구현 가능.
D_QR: 알고리즘 공개해도
      → 고성능 CNN 디코더: 훈련 데이터 + 컴퓨팅 자원 필요
      → 채널별 BER 최적화: 수년간의 실험 데이터
      → Phase 2+ 패턴 인식: 학습된 모델이 핵심 IP

즉, 스펙을 공개해도 잘 작동하는 구현체는 따로 판매 가능
(Linux는 무료지만 Red Hat은 연간 수조 원 매출)
```

# 3. 수익화 경로 4가지

## 경로 1 — 특허 + 라이선싱

```
대상: D_QR 인코딩 방식, 채널별 ECC 설계, 다차원 마스킹 알고리즘

절차:
  1. 국내 특허 출원 (선출원일 확보)
  2. PCT 국제 출원 (30개국+ 확장)
  3. 등록 후 기업 라이선싱

수익 구조:
  기업이 D_QR을 제품에 사용할 때 → 1회성 or 연간 라이선스 비용

예시:
  QUALCOMM: CDMA 특허로 연간 수조 원 수익
  InterDigital: LTE 특허 풀에서 수백억 수익

현실적 리스크:
  → 특허 출원 비용: 국내 수백만 원, PCT 수천만 원
  → 특허 침해 소송: 대기업 상대로 혼자 싸우기 어려움
  → 회피 설계(design-around): 기업들이 약간 다르게 구현
```

**적합도:** ⭐⭐⭐ (유효하나 혼자 하기 어려움)

## 경로 2 — 오픈 스펙 + 생태계 수익

```
모델: 스펙은 무료 공개 → 구현체(SDK)와 서비스는 유료

구체적 실행:
  ① D_QR 스펙 문서 공개 (오픈 표준)
  ② 고성능 공식 SDK 유료 판매
     - Python SDK: $99/월 (개인)
     - Enterprise SDK: $999/월 (기업)
  ③ 클라우드 API: 인코딩/디코딩 API
     - $0.001/호출 (대량 사용 시 볼륨 할인)
  ④ 엔터프라이즈 지원 계약

유사 사례:
  Linux (무료) → Red Hat ($3.4조 매출)
  Android (무료) → Google Play ($490억 매출)
  MySQL (무료) → Oracle 엔터프라이즈 ($수십억)
```

**적합도:** ⭐⭐⭐⭐ (장기적으로 가장 안정적)

## 경로 3 — 특정 산업 수직 SaaS

```
D_QR 기술 자체보다 D_QR을 활용한 솔루션 판매

타깃 산업별 솔루션:

의약품 위변조 방지:
  → D_QR로 약품 패키지에 대용량 정보 + 위변조 불가 구조색 채널
  → 제약사 대상 구독 서비스: $10,000/월
  → 글로벌 의약품 위변조 시장: $200억+

명품 인증:
  → D_QR + Neural 채널 = 복제 불가능한 인증 코드
  → 에르메스, 루이비통 등 명품 브랜드 대상
  → 1개 브랜드 계약 = 수억 원

물류/공급망:
  → 기존 QR의 용량 한계를 D_QR로 대체
  → DHL, FedEx 등 물류 기업 대상

정부/ID:
  → 여권, 신분증 D_QR 시스템
  → 정부 조달 계약 = 안정적 수익
```

**적합도:** ⭐⭐⭐⭐⭐ (가장 빠른 수익, 명확한 고객)

## 경로 4 — 연구 → 스카우트 or 스타트업

```
경로 A: 논문 발표 → 대기업 스카우트
  → D_QR Phase 1 프로토타입 완성
  → 국제 학술지 논문 제출 (IEEE Transactions on Image Processing 등)
  → 구글, 삼성, 네이버 등에서 스카우트 제안
  → 회사 내에서 D_QR 개발 계속

경로 B: VC 투자 → 스타트업
  → 프로토타입 + 특허 출원
  → 엔젤/시드 투자 유치 (수억 원)
  → Phase 1~2 제품화
  → Series A (수십억) → 글로벌 확장
```

**적합도:** ⭐⭐⭐ (불확실성 높으나 잠재 규모 가장 큼)

## 4.1 비교표

| 경로 | 수익 시작 시기 | 수익 규모 | 리스크 | 혼자 가능? |
|------|------------|---------|-------|---------|

## 4.2 추천 조합 (현실적 경로)

```
Step 1 (지금): 특허 출원
  → 아이디어가 있을 때 선출원일 확보
  → 비용: 국내 출원 수백만 원 (특허 전문가 필요)

Step 2 (6개월~1년): Phase 1 프로토타입 완성
  → encoder.py + renderer.py + decoder.py
  → 왕복 테스트 통과 = "작동하는 증거"

Step 3 (1년): 논문 제출
  → IEEE 또는 Pattern Recognition Letters 등
  → 학술 신뢰성 확보

Step 4 (1~2년): 의약품/물류 한 곳 파일럿 계약
  → 경로 3 (수직 SaaS)의 첫 번째 고객
  → "실제 돈이 들어오는 증거"

Step 5 (2년+): SDK API 서비스 런칭
  → 경로 2 (오픈 스펙 + SDK) 본격화
  → 커뮤니티 생태계 구축

Step 6 (3년+): 상황에 따라 경로 4 선택
  → 스카우트 or VC 투자
```

# 7. 리스크 분석

## 7.1 핵심 리스크

**리스크 1: 기술 리스크**
```
"D_QR이 실제로 작동하지 않을 수 있다"
  → 색상 채널 BER이 예상보다 나쁠 수 있음
  → Phase 1 프로토타입이 이를 검증
  → 리스크 해소 방법: 빨리 만들어보기
```

**리스크 2: 경쟁 리스크**
```
"JAB Code가 이미 있다"
  → JAB Code는 ISO 표준화 중이지만 H/S/V 독립 채널 없음
  → 패턴/주파수 차원도 없음
  → D_QR의 차별점이 명확하면 경쟁 가능

"대기업이 비슷한 걸 만들 수 있다"
  → 특허 출원이 유일한 방어 수단
```

**리스크 3: 시장 리스크**
```
"아무도 QR 대신 D_QR을 쓰지 않을 수 있다"
  → QR은 이미 수십억 개 기기에 내장됨
  → D_QR이 표준 대체가 아닌 "추가 옵션"으로 포지셔닝 필요
  → 특정 산업(의약품, 물류)에서 먼저 정착
```
