# 2. 기존 코드 시스템 용량 분석

## 2.1 표준 QR 코드 (Version 5, ECC-M)

```
데이터 모듈: 1,066개
비트/모듈: 1 bit (이진)
총 비트: 1,066 bits
ECC 오버헤드 (ECC-M): ~44%
실효 데이터 비트: 1,066 × 0.56 = 597 bits = 74 bytes
```

공식 수치 (Version 5 ECC-M): **77 bytes** (실측값과 근사 일치 ✅)

## 2.2 JAB Code (8색, ECC-M)

```
데이터 모듈: 1,066개 (동일 크기 가정)
비트/모듈: 3 bits (8색 = 2³)
총 비트: 1,066 × 3 = 3,198 bits
ECC 오버헤드: ~44% (채널별 독립 ECC)
실효 데이터 비트: 3,198 × 0.56 = 1,791 bits = 224 bytes
```

QR 대비 이론: **3배**, 실제 JAB Code 스펙: **~2.5배** = **~193 bytes**

## 2.3 HCCB (Microsoft, 8색 삼각형)

```
삼각형 요소 사용으로 동일 면적에 더 많은 심볼 배치 가능
실험값: 2,000 bytes / 제곱인치 @ 600 DPI
QR 대비: ~2.5~3배 (인쇄 품질에 크게 의존)
```

# 3. D_QR 이론 용량 계산

## 3.1 Phase 1 (색상 3채널)

$$B_{module}^{P1} = b_{c_1} + b_{c_2} + b_{c_3} = 3 + 2 + 2 = 7 \text{ bits}$$

```
데이터 모듈: 1,066개
비트/모듈: 7 bits
총 비트: 1,066 × 7 = 7,462 bits
ECC 오버헤드 (채널별 평균 ECC-M): ~40%
실효 데이터 비트: 7,462 × 0.60 = 4,477 bits = 560 bytes
```

**QR 대비 이론: 7배, 실효 예상: ~7.3배 = 560 bytes**

## 3.2 Phase 2 (색상 + 패턴)

$$B_{module}^{P2} = 7 + b_{p_1} + b_{p_2} = 7 + 3 + 2 = 12 \text{ bits}$$

```
총 비트: 1,066 × 12 = 12,792 bits
ECC 오버헤드 (패턴 채널 더 강한 ECC): ~45%
실효 데이터 비트: 12,792 × 0.55 = 7,036 bits = 879 bytes
```

**QR 대비 이론: 12배, 실효 예상: ~11.4배 = 879 bytes**

## 3.3 Phase 3 (색상 + 패턴 + 주파수, 화면 전용)

$$B_{module}^{P3} = 12 + b_{f_1} + b_{f_2} = 12 + 2 + 1 = 15 \text{ bits}$$

```
총 비트: 1,066 × 15 = 15,990 bits
ECC 오버헤드: ~50% (주파수 채널이 취약)
실효 데이터 비트: 15,990 × 0.50 = 7,995 bits = 999 bytes
```

**QR 대비 이론: 15배, 실효 예상: ~13배 = 999 bytes**

# 4. 현실 보정 후 실효 용량

## 4.1 채널별 BER 모델 (추정값)

실제 스마트폰 카메라 기반 디코딩 시 예상 오류율.  
*실측 검증 필요 — 현재는 JAB Code 논문 및 색상 QR 연구에서 추정.*

| 채널 | 기호 | 이상적 BER | 조명 불량 시 | 기울기 15° 시 |
|------|------|-----------|-----------|------------|
| 색조 (Hue) | $c_1$ | 3~5% | 8~12% | 5~7% |
| 채도 (Saturation) | $c_2$ | 10~15% | 20~30% | 15~20% |
| 명도 (Value) | $c_3$ | 5~8% | 10~15% | 8~10% |
| 패턴 방향 | $p_1$ | 5~8% | 10~15% | 15~25% |
| 패턴 종류 | $p_2$ | 8~12% | 20~30% | 20~30% |

## 4.2 BER 보정 후 실효 비트

각 채널의 실효 비트 = 이론 비트 × (1 - BER) × ECC 이득:

| 채널 | 이론 비트 | BER (평균) | ECC 이득 | 실효 비트 |
|------|--------|----------|---------|---------|
| $c_1$ | 3 | 5% | 1.8× | ~5.13 |
| $c_2$ | 2 | 12% | 1.5× | ~2.64 |
| $c_3$ | 2 | 7% | 1.7× | ~3.16 |
| **Phase 1 합계** | **7** | | | **~4.5 bits (실효)** |

*ECC 이득 = 손실된 데이터를 복원하므로 원시 BER보다 높은 실효 용량*

## 4.3 보수적 추정 (안정적 사용 기준)

Phase 1 D_QR의 보수적 실효 용량:

```
7 bits/module (이론)
× 0.65 (BER 손실)
× 1.7 (ECC 복원)
= 7.73 bits/module → ~4.5 bits/module (순 실효)
```

**실효 용량 추정: QR의 4~5배 = 308~385 bytes** (Version 5 기준)

# 6. 채널별 신뢰도 모델

## 6.1 채널 독립성 가정

핵심 가정: 채널 간 오류가 독립적이어야 한다.  
즉, $c_1$이 오류가 났다고 $c_2$도 오류일 확률이 높아지면 안 된다.

```
독립 채널의 경우:
전체 오류 확률 P(error) = P(c₁ error) × P(c₂ error) × ...
→ 각 채널 오류가 독립이면 동시 오류 확률 매우 낮음

종속 채널의 경우 (e.g., 조명 변화):
조명이 나쁘면 색조, 채도, 명도 모두 동시에 틀릴 수 있음
→ ECC가 무의미해질 수 있음
```

## 6.2 채널 간 상관 오류 대책

조명 변화가 여러 채널에 동시 영향을 주는 경우 대책:

1. **화이트 밸런스 보정**: 파인더 패턴의 흑/백을 기준으로 색 보정
2. **채널 간 중복 인코딩**: 중요 데이터를 색조(c₁)와 명도(c₃)에 동시 저장
3. **온도 불변 색 공간**: HSV 대신 L\*a\*b\* 색 공간 사용 검토

## 6.3 BER vs 거리/각도 예상 그래프

```
BER (%)
  30 |         *p₂
     |      *p₁  
  20 |   *c₂
     |
  10 |      *c₃
     |   *c₁
   5 |
     |
   0 +---------------------------→ 거리/기울기
      정면    15°    30°    45°
```

p₂(패턴 종류) 채널이 기울기에 가장 취약 → Phase 2 이후에서 CNN 디코더 필수.

# 7. 결론 및 시사점

## 7.1 달성 가능한 현실적 목표

| 단계 | 목표 | 달성 조건 |
|------|------|---------|
| Phase 1 | QR의 4~5배 용량 | 색상 3채널 안정적 구현 |
| Phase 2 | QR의 8~10배 용량 | CNN 패턴 디코더 + 충분한 해상도 |
| Phase 3 | QR의 12~14배 용량 | 화면 전용, 높은 해상도 |

## 7.2 검증이 필요한 핵심 항목

1. **색상 팔레트 BER 실측** ❌ 미완
   - 8색 팔레트를 화면에 렌더링 → 카메라 촬영 → 색 인식 오율 측정
   - 조명 조건 3가지 이상 (형광등, 햇빛, 어두운 방)

2. **왕복 테스트** ❌ 미완
   - 임의 데이터 → encode → render → decode → 원본 일치 확인

3. **ECC 레이트 최적화** ❌ 미완
   - Phase 1 각 채널의 실측 BER에 기반한 최적 ECC 레이트 결정

## 7.3 경쟁 우위 포인트

```
D_QR의 차별점:
1. 색상 채널 분리 (JAB는 색상을 단일 심볼로 처리, D_QR은 H/S/V 독립 채널)
2. 채널별 독립 ECC → 오류 특성이 다른 채널에 맞춤 ECC
3. 확장 가능한 차원 구조 (Phase 1→2→3→Neural)
4. 딥러닝 친화적 설계 (텐서 표현이 CNN과 자연스럽게 호환)
```
