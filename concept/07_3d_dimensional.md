# 07. D_QR 3D/다차원 물리 공간 연구

> **보안 주의**: 이 문서는 특허 출원 전 비공개 유지 필수

---

## 1. 핵심 질문: 물리 공간이 정보 차원을 얼마나 제공하는가?

현재 D_QR(exp1~exp4)는 **2D 평면 표면**만 사용:

```
2D 코드:  I(x, y) → data
           └ 2개 공간 차원
```

물리 세계는 3+1차원(공간 3 + 시간 1)이고, 빛은 파장·편광·위상·OAM을 추가 차원으로 제공:

```
완전 다차원: D(x, y, z, θ, φ, λ, σ, l, t) → data
             │  │  │   │  │  │  │  │  └ 시간
             │  │  │   │  │  │  │  └─── OAM 모드 수
             │  │  │   │  │  │  └────── 편광 상태
             │  │  │   │  │  └───────── 파장(색상)
             │  │  │   └──┴──────────── 관측 각도
             └──┴──┴────────────────── 공간 위치
```

**핵심 통찰**: 각 독립 물리 차원이 RS ECC로 보호되는 독립 데이터 채널이 될 수 있다.

## 2. 물리 차원 카탈로그

| 차원 | 물리 현상 | 추가 bits/셀 | 구현 방법 | 난이도 | 가용 시기 |
|------|---------|-----------|---------|--------|---------|
| **z (깊이)** | 부조 높이 | +2 | 3D프린터 + 구조광 | ★★☆ | **지금** |
| **θ, φ (각도)** | 렌티큘러 | ×N | 렌티큘러 렌즈 | ★★★ | 2~3년 |
| **3방향 투영** | 섀도우 코드 | ×3 | 3D 설계 | ★★★ | 2~3년 |
| **λ (파장)** | 메타서피스 | ×36 | 나노 제조 | ★★★★★ | 15년+ |
| **σ (편광)** | TE/TM | ×2 | 편광 필터 | ★★★☆ | 3~5년 |
| **l (OAM)** | 나선 위상 | ×N | 나선 위상판 | ★★★★ | 10년+ |
| **t (시간)** | 동적 패턴 | ×fps | E-Ink / 화면 | ★★☆ | **지금** |
| **τ (위상)** | 간섭 패턴 | 연속 | 레이저 간섭계 | ★★★★ | 연구 단계 |

## 3. Z축 부조 인코딩 (Phase 5 구현 대상)

### 3.1 수식 정의

```
기존(exp4):  T_flat[q,r] ∈ {0,...,63}     — 6비트/셀 (삼각형 패턴)
Phase 5:     T_3D[q,r]  = (v_tri, v_z)
               v_tri ∈ {0,...,63}         — 6비트: 표면 삼각형 패턴
               v_z   ∈ {0,1,2,3}          — 2비트: 높이 레벨
             → 8비트/셀 = 1바이트 (RS와 자연 정렬!)
```

### 3.2 높이 레벨 설계

```
z_levels = [0, h, 2h, 3h]   h = 물리 높이 단위 (예: 0.5mm)

실제 물리 제조:
  - FDM 3D 프린터: 레이어 해상도 0.1~0.2mm → h = 0.2mm 실현 가능
  - CNC 가공: h = 0.5mm (금속 각인)
  - 레이저 각인: h = 0.3mm (깊이 3레벨)
```

### 3.3 디코딩 방법

| 방법 | 장비 | 정확도 | 상용화 |
|------|------|--------|--------|
| 구조광(structured light) | 전용 스캐너 | ±0.05mm | 산업용 |
| 스테레오 비전 | 스마트폰 2카메라 | ±0.5mm | 신형 폰 |
| ToF 센서 | 아이폰 LiDAR | ±5mm | 고급 스마트폰 |
| 사선 촬영 + 그림자 분석 | 일반 카메라 + 조명 | ±1mm | 소프트웨어만 |

**Phase 5 프로토타입**: 완벽 정렬 가정, 높이 값을 메타데이터로 전달 (소프트웨어 시뮬레이션)

### 3.4 용량 비교

| 격자 반지름 | exp4 (6비트) | Phase 5 (8비트) | 증가율 |
|-----------|------------|----------------|--------|
| r=8       | 96 B       | 152 B          | +58%   |
| r=12      | 234 B      | 387 B          | +65%   |
| r=18      | 601 B      | 802 B          | +33%   |
| r=25      | 1141 B     | 1622 B         | +42%   |

## 4. 다시점 인코딩 (Multi-view)

### 4.1 원리

렌티큘러 렌즈(lenticular lens)를 D_QR 위에 부착하면,
**관측 각도에 따라 다른 셀 패턴이 보임** → 각 각도가 독립 데이터 채널:

```
각도 θ₁ → Pattern A (데이터 A)
각도 θ₂ → Pattern B (데이터 B)
각도 θ₃ → Pattern C (데이터 C)
각도 θ₄ → Pattern D (데이터 D)
→ 1장의 코드에 4× 용량
```

### 4.2 현재 기술 수준

- 상업용 렌티큘러 인쇄: 3~4개 뷰, 인쇄 해상도 300dpi 필요
- 나노임프린트 렌티큘러: 10~20개 뷰 가능
- 메타렌즈(POSTECH 2025): 36채널 — 이것이 다시점의 극한

## 5. 3D 투영 코드 (Shadow Code)

### 5.1 핵심 아이디어

**1개의 3D 오브젝트 → 3방향 투영 = 3개 독립 2D D_QR 코드**

```
3D 오브젝트 O[x,y,z]
  → 투영 P_xy = ∫ O dz    (위에서 아래, top-down)  → Code A
  → 투영 P_xz = ∫ O dy    (앞에서 뒤, front view)   → Code B
  → 투영 P_yz = ∫ O dx    (옆에서 옆, side view)    → Code C

3개 카메라로 3방향 촬영 → 3배 용량
```

### 5.2 수학적 제약

세 투영이 독립이려면:
```
P_xy ⊥ P_xz ⊥ P_yz   (정보 이론적 독립성)
```
이는 데이터를 3개 stream으로 분리하여 각 투영에 배분함으로써 달성.

### 5.3 구현 가능성

- 3D 프린팅으로 제작 가능 (현재 기술)
- 3방향 조명 + 3방향 카메라 필요
- 실내 고정 스캐너 환경에서 즉시 실용화 가능
- **특허 가능성 높음** (현재 유사 특허 검색 중)

## 6. 시간 차원 — 4D D_QR

### 6.1 개념

```
정적 코드:  I(x, y)       — 2D
동적 코드:  I(x, y, t)    — 3D (시간 포함)

t 차원 활용:
  - 프레임 k의 삼각형 패턴 = 데이터 레이어 k
  - 30fps × 1초 = 30개 독립 레이어
  - → 단일 화면 크기로 30배 용량
```

### 6.2 현실 제약

| 방식 | 전송 속도 | 디코딩 하드웨어 | 용량 배율 |
|------|---------|------------|---------|
| E-Ink (3fps) | 저속 | 일반 카메라 | ×3 |
| LCD (60fps) | 고속 | 고속 카메라 | ×60 |
| 마이크로LED 디스플레이 | 매우 고속 | 전용 수신기 | ×1000+ |

**응용**: 빛의 속도로 대용량 데이터 전송 — 레이저 통신의 확장 형태

## 7. 정보 이론적 한계

물리 공간이 제공하는 최대 정보 용량:

```
Shannon capacity = B · log₂(1 + S/N)

각 독립 물리 채널이 추가 B를 제공:
  C_total = Σᵢ Bᵢ · log₂(1 + Sᵢ/Nᵢ)

실제 한계:
  - 나노 제조 해상도: ~10nm (파장의 1/40)
  - 광자 1개당 정보: log₂(N) bits (N = 구분 가능 상태 수)
  - 양자 한계: 1 qubit = 무한 정보 (측정 시 collapse)
```
